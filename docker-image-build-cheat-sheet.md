# Шпаргалка по созданию образов в Docker (Docker Image Build)

Создание собственного образа — это процесс сборки изолированного окружения со всеми зависимостями и кодом твоего приложения на основе текстового файла инструкций (`Dockerfile`).

---

## 1. Основные концепции создания образов

* **Dockerfile — основа сборки:** Чтобы создать свой образ, необходим специальный текстовый файл `Dockerfile` (без расширения).
* **Расположение:** Обычно `Dockerfile` помещают в **корне папки** проекта / приложения.
* **Содержимое:** `Dockerfile` содержит пошаговый набор инструкций и команд (какой базовый образ взять, какие файлы скопировать, какие команды выполнить и какой порт открыть).
* **Именование и теги:** При создании образа можно (и рекомендуется) указать понятное **имя (репозиторий)** и **тег (версию)** через флаг `-t`. Если тег не указан, Docker автоматически назначит тег `:latest`.
* **Запуск контейнеров:** На основании готового собранного образа можно создавать и запускать сколько угодно изолированных контейнеров (`docker run`).

---

## 2. Пошаговые этапы жизненного цикла образа

```text
  [Код проекта + Dockerfile] 
              │
              ▼  (docker build)
      ┌───────────────┐
      │  Docker Image │  (Сборка слоев, назначение имени и тега)
      └───────────────┘
         │          │
(docker push)   (docker run)
         │          │
         ▼          ▼
    [Registry]   [Запущенные контейнеры]
   (Docker Hub)
```

1. **Написание Dockerfile:** Описываем шаги окружения и сборки проекта.
2. **Сборка (Build Context):** Запускаем сборку командой `docker build`. Docker отправляет файлы проекта демону и последовательно выполняет инструкции.
3. **Слоистая структура (Layer Caching):** Каждая инструкция в `Dockerfile` формирует свой неизменяемый слой (layer). Если слой не менялся, Docker берет его из кэша, что делает повторную сборку мгновенной.
4. **Тегирование:** Образ получает имя и версию, например: `my-app:1.0` или `my-app:latest`.
5. **Запуск или публикация:** Образ запускается локально через `docker run` или отправляется в удаленный реестр (`docker push`) для деплоя на сервер.

## 3. Базовые инструкции `Dockerfile`

| Инструкция | Описание | Пример |
| :--- | :--- | :--- |
| `FROM` | Базовый образ, на основе которого идет сборка (всегда первая команда). | `FROM node:18-alpine` |
| `WORKDIR` | Задает рабочую директорию внутри контейнера для всех последующих команд. | `WORKDIR /app` |
| `COPY` | Копирует файлы или папки с хоста в контейнер. | `COPY . .` |
| `RUN` | Выполняет команду во время сборки образа (например, установка пакетов). | `RUN npm install` |
| `EXPOSE` | Документирует сетевой порт, который слушает приложение. | `EXPOSE 3000` |
| `ENV` | Устанавливает переменные окружения. | `ENV PORT=3000` |
| `CMD` | Команда по умолчанию, которая выполняется при старте контейнера. | `CMD ["node", "index.js"]` |

## 4. Основные команды для сборки и работы с образами

### Сборка образа
```bash
# Собрать образ из текущей папки (.) и задать имя с тегом
docker build -t my-app:1.0 .

# Собрать образ с тегом latest по умолчанию
docker build -t my-app .

# Собрать образ с явным указанием пути к нестандартному Dockerfile
docker build -f ./Dockerfile.dev -t my-app:dev .

# Собрать образ без использования кэша
docker build --no-cache -t my-app:1.0 .
```

### Просмотр и удаление
```bash
# Посмотреть список локальных образов
docker images

# Присвоить образу дополнительный тег
docker tag my-app:1.0 my-username/my-app:1.0

# Удалить образ
docker rmi my-app:1.0
```

## 5. Полезные рекомендации (Best Practices)

* **Файл `.dockerignore`:** Создавай `.dockerignore` рядом с `Dockerfile`, чтобы исключить ненужные файлы (например, `.git`, `node_modules`, временные файлы, пароли), ускорить сборку и уменьшить вес образа.
* **Используй легковесные базовые образы:** По возможности выбирай версии на базе `alpine` или `slim` (например, `python:3.11-slim`, `node:alpine`).
* **Оптимизируй порядок инструкций для кэша:** Сначала копируй файлы зависимостей (`package.json`, `requirements.txt`), устанавливай их (`RUN npm install`), и только потом копируй весь исходный код (`COPY . .`). Так при изменении кода не придется заново скачивать зависимости.
