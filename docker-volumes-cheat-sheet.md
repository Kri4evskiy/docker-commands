# Шпаргалка по томам в Docker (Docker Volumes & Storage Cheat Sheet)

Хранилища в Docker предназначены для **сохранения данных (Persistence)** вне жизненного цикла контейнера и для **обмена файлами** между хостом и контейнером (или между несколькими контейнерами).

---

## 1. Типы хранилищ в Docker

В Docker существует 3 основных типа монтирования:

```
┌─────────────────────────────────────────────────────────────┐
│                       HOST MACHINE                          │
│                                                             │
│  ┌──────────────────────┐         ┌──────────────────────┐  │
│  │   Docker Volumes     │         │     Bind Mounts      │  │
│  │ (/var/lib/docker/...)│         │ (любая папка хоста)  │  │
│  └──────────┬───────────┘         └──────────┬───────────┘  │
└─────────────┼────────────────────────────────┼──────────────┘
              │                                │
              ▼                                ▼
      ┌───────────────┐                ┌───────────────┐
      │  Контейнер 1  │                │  Контейнер 2  │
      │ (База данных) │                │ (Код проекта) │
      └───────────────┘                └───────────────┘
```

| Тип | Где хранятся данные | Для чего используется | Преимущества / Особенности |
| :--- | :--- | :--- | :--- |
| **Named Volumes** *(Именованные тома)* | Управляются Docker (`/var/lib/docker/volumes/` в Linux/WSL) | Базы данных (MySQL, Postgres, Mongo), кэши, персистентные данные | ⭐ **Лучший выбор для БД**. Высокая производительность, изолированность, легко бэкапить. |
| **Anonymous Volumes** *(Анонимные тома)* | Папка со случайным хэшем в недрах Docker | Временное исключение папок (например, `node_modules`) | Создаются без имени. При `docker compose down` без `-v` могут накапливаться в системе. |
| **Bind Mounts** *(Монтирование с хоста)* | Конкретная папка/файл на вашем ПК (относительный или абсолютный путь) | Разработка: исходный код, конфиги (`nginx.conf`) | Изменения на хосте мгновенно видны в контейнере (Hot Reload). Зависят от структуры папок хоста. |
| **tmpfs Mounts** | В оперативной памяти хоста (RAM) | Секреты, сессии, временные файлы высокой скорости | Данные не пишутся на диск и стираются при остановке контейнера. |

## 2. Использование Volumes в `docker-compose.yml`

### Пример с Базой Данных (MySQL) и Бэкендом (Node.js)

```yaml
services:
  # 1. Сервер приложения (Использует Bind Mount для горячей перезагрузки кода)
  api:
    build: ./api
    ports:
      - "5555:5000"
    volumes:
      # Bind mount: связываем локальный код с папкой внутри контейнера
      - ./api:/app
      # Anonymous volume: защищает node_modules контейнера от перезаписи хостом!
      - /app/node_modules
    environment:
      - NODE_ENV=development

  # 2. База данных (Использует Именованный том для сохранения данных)
  mysql:
    image: mysql:8.0
    restart: always
    environment:
      MYSQL_ROOT_PASSWORD: password
      MYSQL_DATABASE: time_db
    ports:
      - "3306:3306"
    volumes:
      # <имя_тома>:<путь_в_контейнере>[:флаги]
      - mysql_data:/var/lib/mysql

  # 3. CloudBeaver (Именованный том для сохранения настроек и подключений)
  dbeaver:
    image: dbeaver/cloudbeaver:latest
    restart: always
    ports:
      - "8888:8978"
    volumes:
      - cloudbeaver_data:/opt/cloudbeaver/workspace
    depends_on:
      - mysql

# КОРНЕВОЙ БЛОК: Обязательно объявляем все именованные тома!
volumes:
  mysql_data:
    # Можно указать внешний том: external: true (если создан заранее вручную)
  cloudbeaver_data:
```

## 3. Пути монтирования для популярных Баз Данных

При настройке томов для БД важно указывать правильный внутренний путь:

| СУБД / Сервис | Внутренний путь контейнера (куда монтировать том) |
| :--- | :--- |
| **MySQL / MariaDB** | `/var/lib/mysql` |
| **PostgreSQL** | `/var/lib/postgresql/data` |
| **MongoDB** | `/data/db` |
| **Redis** | `/data` |
| **CloudBeaver** | `/opt/cloudbeaver/workspace` |
| **Nginx** | `/usr/share/nginx/html` (контент) или `/etc/nginx/conf.d` (конфиги) |

## 4. Безопасность и Best Practices (Как делать правильно)

### 1. Безопасный запуск и удаление контейнеров
* `docker compose down` — останавливает и удаляет контейнеры и сети, но **НЕ трогает ваши данные в именованных томах**. База данных останется в сохранности.
* `docker compose down -v` — ⚠️ **ОПАСНО**: флаг `-v` (`--volumes`) **удаляет все тома проекта вместе со всеми данными**! Используйте только если хотите полностью сбросить БД до начального состояния.

### 2. Защита от случайной перезаписи (`:ro` - Read Only)
Если контейнеру нужен доступ к файлам конфигурации хоста только для чтения, используйте флаг `:ro`:
```yaml
volumes:
  - ./nginx.conf:/etc/nginx/nginx.conf:ro
```

### 3. Решение проблемы с `node_modules` при Bind Mount
Когда вы монтируете `- .:/app`, пустая или несовместимая папка `node_modules` с Windows может затереть `node_modules` внутри Linux-контейнера.
**Решение:** добавить анонимный том для `node_modules`:
```yaml
volumes:
  - .:/app              # Код синхронизируется
  - /app/node_modules   # node_modules изолированы внутри контейнера
```

### 4. Внешние тома (External Volumes)
Если вам нужно, чтобы том гарантированно не был удален при любых манипуляциях с проектом или использовался несколькими `docker-compose.yml`:
1. Создать вручную: `docker volume create production_mysql_data`
2. В `docker-compose.yml`:
```yaml
volumes:
  mysql_data:
    external: true
    name: production_mysql_data
```

## 5. Основные CLI команды для управления Volumes

| Команда | Описание |
| :--- | :--- |
| `docker volume ls` | Список всех томов в системе. |
| `docker volume create <имя>` | Создать новый именованный том вручную. |
| `docker volume inspect <имя>` | Подробная информация о томе (включая `Mountpoint` — путь на диске). |
| `docker volume rm <имя>` | Удалить конкретный неиспользуемый том. |
| `docker volume prune` | Удалить **все неиспользуемые** анонимные и именованные тома (освобождает место). |

### Примеры с `docker run`:

* **Именованный том:**
  ```bash
  docker run -d -v my_db_data:/var/lib/mysql -e MYSQL_ROOT_PASSWORD=password mysql:8.0
  ```
* **Bind Mount (относительный путь):**
  ```bash
  docker run -d -p 80:80 -v ${PWD}/html:/usr/share/nginx/html:ro nginx
  ```
