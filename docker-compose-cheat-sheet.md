# Шпаргалка по Docker Compose (docker-compose cheat sheet)

**Docker Compose** — это инструмент для декларативного описания, сборки и запуска многоконтейнерных приложений с помощью единого конфигурационного файла `docker-compose.yml` (или `compose.yaml`).

---

## 1. Ключевые преимущества Docker Compose

* **Декларативный подход:** Вместо длинных и сложных команд `docker run` со всеми флагами вся конфигурация системы (порты, тома, переменные окружения) описывается в структурированном YAML-файле.
* **Запуск одной командой:** Все взаимосвязанные сервисы (например, Frontend + Backend + PostgreSQL + Redis) запускаются и останавливаются одной командой (`docker compose up` / `docker compose down`).
* **Автоматическая сборка образов:** Compose может автоматически собрать нужные образы по `Dockerfile` каждого сервиса прямо перед запуском (блок `build`).
* **Изолированная общая сеть "из коробки":** При старте Compose автоматически создает изолированную сеть (`bridge`) для проекта и помещает в нее все описанные контейнеры.
* **Встроенный Service Discovery (DNS по имени сервиса):** Контейнерам не нужно знать IP-адреса друг друга. Они обращаются между собой по **именам сервисов** (например, `http://backend:8000` или `postgres://db:5432`).

## 2. Структура файла `docker-compose.yml`

```yaml
services:
  # 1. Сервис приложения (собирается из Dockerfile)
  web:
    build: .                          # путь к папке с Dockerfile
    ports:
      - "8080:80"                     # <host_port>:<container_port>
    volumes:
      - .:/app                        # bind mount для горячей перезагрузки
    environment:
      - NODE_ENV=development
      - DB_HOST=database              # обращение к базе по имени сервиса!
    depends_on:
      - database                      # порядок запуска (после базы данных)
    restart: always

  # 2. Сервис базы данных (готовый образ)
  database:
    image: postgres:15-alpine
    environment:
      POSTGRES_DB: mydb
      POSTGRES_USER: user
      POSTGRES_PASSWORD: secretpassword
    volumes:
      - db_data:/var/lib/postgresql/data  # именованный том

# Описание именованных томов
volumes:
  db_data:
```

## 3. Основные директивы в `docker-compose.yml`

| Директива | Назначение | Пример / Аналог в `docker run` |
| :--- | :--- | :--- |
| `services` | Корневой блок со списком всех запускаемых контейнеров. | — |
| `image` | Готовый образ из реестра (Docker Hub). | `docker run nginx` |
| `build` | Путь к локальной папке с `Dockerfile` для сборки. | `docker build .` |
| `ports` | Проброс портов с хоста в контейнер. | `-p 8080:80` |
| `volumes` | Подключение томов (именованных или bind mounts). | `-v ./src:/app` |
| `environment` | Переменные окружения внутри контейнера. | `-e KEY=value` |
| `env_file` | Подключение файла с переменными (`.env`). | `--env-file .env` |
| `depends_on` | Указывает очередность запуска контейнеров. | — |
| `restart` | Политика перезапуска (`always`, `unless-stopped`, `on-failure`). | `--restart always` |
| `networks` | Пользовательские сети (если нужна кастомная изоляция). | `--network` |

## 4. Главные команды Docker Compose

> [!NOTE]
> В современном Docker используется синтаксис `docker compose` (через пробел, Compose V2). Старый синтаксис через дефис (`docker-compose`) считается устаревшим.

### Запуск и остановка
```bash
# Запустить все сервисы в фоновом режиме (-d)
docker compose up -d

# Собрать/пересобрать образы и запустить сервисы
docker compose up -d --build

# Остановить и удалить контейнеры и сеть проекта
docker compose down

# Остановить и удалить контейнеры, сеть И именованные тома (очистить данные БД)
docker compose down -v
```

### Мониторинг и управление
```bash
# Посмотреть статус контейнеров текущего compose-проекта
docker compose ps

# Посмотреть логи всех сервисов в реальном времени
docker compose logs -f

# Посмотреть логи конкретного сервиса (например, web)
docker compose logs -f web

# Перезапустить конкретный сервис или весь проект
docker compose restart web
```

### Выполнение команд внутри сервисов
```bash
# Запустить команду в уже работающем контейнере сервиса
docker compose exec web sh

# Запустить разовую команду в новом отдельном контейнере сервиса
docker compose run --rm web npm test
```

## 5. Важные нюансы и Best Practices

1. **Файлы `.env`:**
   Compose автоматически считывает файл `.env` в той же директории и подставляет значения в переменные `${VAR_NAME}` внутри `docker-compose.yml`. Не коммитьте секретные `.env` файлы в Git!

2. **Имена проектов (Project Name):**
   По умолчанию Compose называет создаваемые контейнеры, сети и тома с префиксом имени текущей папки (например, `myapp-web-1`, `myapp_default`).

3. **Сетевое взаимодействие:**
   Вам **не нужно** вручную пробрасывать порты между контейнерами через `ports:`. Внутри общей compose-сети все порты контейнеров уже доступны друг другу по имени сервиса. `ports:` нужен **только** для доступа с хост-машины (из браузера/Postman).
