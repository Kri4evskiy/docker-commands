# Шпаргалка по архитектуре и компонентам Docker

В основе Docker лежит архитектура клиент-сервер. Взаимодействие строится просто: клиент отдает команду, служба ее выполняет на хост-машине.

---

## 1. Основные компоненты (Архитектура)

### Client (Клиент / CLI)
* **Что это:** Командная строка (терминал), с которой ты взаимодействуешь.
* **Как работает:** Ты вводишь команды (например, `docker run`), и клиент отправляет их фоновой службе (Daemon) через API.

### Daemon (Служба / Docker Daemon)
* **Что это:** «Мозг» и главный фоновый процесс Docker на твоем компьютере.
* **Как работает:** Принимает запросы от клиента, управляет жизненным циклом объектов: скачивает образы, создает сети, запускает контейнеры и следит за ними.

### Host (Хост)
* **Что это:** Физический или виртуальный компьютер (твоя ОС), на котором установлен и запущен Docker. На нем физически крутятся демон, контейнеры и хранятся образы.

---

## 2. Сущности, с чем мы работаем (Объекты Docker)

### Image (Образ)
* **Что это:** Неизменяемый шаблон или «чертеж» (например, образ с Ubuntu, Node.js или базой данных PostgreSQL).
* **Важно:** Образ сам по себе не работает — это просто заархивированный набор файлов и инструкций. Из одного образа можно запустить сколько угодно одинаковых контейнеров.

### Container (Контейнер)
* **Что это:** Запущенный экземпляр образа. Это изолированная среда, где реально выполняется твое приложение со всеми его зависимостями.

### Repository (Репозиторий)
* **Что это:** Коллекция версий (тегов) одного конкретного образа. Например, репозиторий `nginx` содержит версии `latest`, `1.25`, `alpine` и т.д.

### Registry (Реестр)
* **Что это:** Глобальное хранилище репозиториев (например, официальный публичный Docker Hub или приватные облачные хранилища вроде AWS ECR / GitHub Packages). Отсюда ты скачиваешь нужные готовые образы командой `docker pull`.

### Volume (Том / Хранилище)
* **Что это:** Механизм для постоянного хранения данных (persistent data), изолированный от жизненного цикла контейнера.
* **Зачем нужно:** Контейнеры по умолчанию «одноразовые» — при их удалении все новые данные внутри стираются. Тома сохраняют файлы (базы данных, загрузки, конфиги) на хосте, поэтому при удалении или пересоздании контейнера данные не теряются.

### Network (Сеть)
* **Что это:** Виртуальная сеть, которая изолирует контейнеры или объединяет их для безопасного взаимодействия.
* **Зачем нужно:** Позволяет контейнерам общаться между собой по имени (например, бэкенд обращается к базе данных по адресу `db:5432` без необходимости знать ее меняющийся IP-адрес).

---

## 3. Экосистема Docker: что идет дальше (Важные дополнения)

Когда ты научишься запускать одиночные контейнеры, тебе неизбежно понадобятся инструменты для управления ими в реальных проектах:

### Docker Compose
* **Что это:** Инструмент для запуска и управления множеством контейнеров одновременно.
* **Зачем нужно:** Если твоему сайту нужна база данных и кэш (Redis), вместо того чтобы запускать каждый контейнер отдельной длинной командой, ты описываешь всю систему в одном текстовом файле (`docker-compose.yml`) и запускаешь одной командой `docker compose up`.

### Оркестраторы (например, Kubernetes или Docker Swarm)
* **Что это:** Системы управления контейнерами на уровне кластера (множества серверов).
* **Зачем нужно:** Если твой сайт начинают посещать миллионы людей, один сервер и один контейнер падают от нагрузки. Оркестраторы автоматически масштабируют приложение (создают копии на разных серверах), распределяют трафик (балансировка) и перезапускают упавшие контейнеры. Docker отвечает за упаковку и запуск приложения на одной машине, а Kubernetes управляет тысячами таких контейнеров на сотен серверов в компании.
